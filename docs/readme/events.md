### イベント「うな○ー大量発生クエスト」（public/src/swarm/）
グランシティの時計の棟の門をくぐって中庭に入ると、「うな○ー大量発生クエスト」の表示が出て、受けるかを聞く。**Y**（Enter も可）か画面の「はい」で始まり、**N** か「いいえ」で閉じる（断ったときと、聞いている間に中庭から出たときは、いったん中庭の外へ出て入り直すとまた聞く）。PC でマウスを固定している間はボタンを押せない（クリックは攻撃になる）ので、キーで選ぶ。始まると、まわりの棟の屋上の縁に敵キャラ「うな○ー」が現れ、両手をあげて身がまえてから、大の字のうつぶせで中庭へ落ちてくる（落ちてくる所の地面に赤い輪）。べちゃっと着地して起き上がり、走って寄ってきて、ためてから体当たりする。
- 数: 一度に出るのは 50 体まで（`event.js` の `ALIVE`）。最初は約 0.25 秒おきに 50 体まで落ちてきて、倒すと次が落ちてくる。全部で 100 体（`TOTAL`）倒すとクリア（画面にタイム）。
- 攻撃: 剣の軌跡が出ている間に、届く範囲（`REACH`・`ARC`。`server/room.js` の対戦の当たりと同じ考え方）にいる敵に当たる。敵の体力は 2、1・2 撃目は 1、3 撃目（回転斬り）は 2。当たると一瞬止まって赤く光り、のけぞって下がる。倒すと吹き飛んでくるくる回り、色の水玉がはじけて消える。
- やられる: 体当たり 5 回でやられる（体力 100、1 回 20。当たった後 1 秒は当たらない。倒しても体力は戻らない）。やられると、近くの敵 16 体が次々に飛び乗ってうつぶせで重なり（`startPile()`。高さ約 4 m の山。それ以上は乗らない）、ほかの敵は山のまわりに集まり続ける（敵は出し続ける。攻撃はしない）。重なり終わると画面の下に小さく 1 行で「やられた… ○ 体たおした」と OK が出る（潰されている所が隠れないように）。OK（Enter / Space / ボタン）で敵が消え、時計の棟の門の外へ戻る（門をくぐると再挑戦）。中庭から 80 m 以上離れて 4 秒たつと（R でスタートに戻ったときも）敵はいなくなる。
- クリア: 100 体たおすと、3 倍の大きさで金色に光る「黄金のうな○ー」（`Herd` の `gold`）が上空 45 m からきらきらと降りてきて、言葉のあと「伝説のうな○ー刀」を授けてくれる（頭の上に現れた刀が、回りながらプレイヤーの前へ降りてくる）。受け取ると剣が金色になり（幅広の金の刃に水玉、金の軌跡。`character.js` の `setLegend()`）、黄金のうな○ーは手を振って空へ帰る。持っていることはブラウザに覚え（`localStorage` の `totsuka.unaLegend`）、次に開いたときも金色のまま。URL に `?nolegend` で元の剣に戻して忘れる。表示の OK は Enter / Space / ボタン（`stepEnding()`）。
- 自分の画面だけの出来事（マルチプレイのほかの人には見えない）。URL に `?noswarm` で無効、`?swarm` で開いてすぐ中庭で、聞かずに始める（確認用）。撮影（`?shot`）では `?swarm` が無ければ始まらない。
- 見た目（`model.js`）: 白いおもちのような体に水玉、頭にふた葉、にんまり口、太い灰色の線の手足。絵は canvas で描き（画像ファイルなし）、平たい板（体の表・裏・手足）を紙の人形のように動かす。板の種類ごとに `InstancedMesh` 1 つなので、何体いても描画は数回。戸塚区のキャラクターのパロディとして、持ち主の依頼で作った（名前は持ち主の指定。形・顔・頭の飾りは別物にしてある）。
- 落ちてくる所は、中庭に面した屋上の縁（`SITE.edges`）に 2.5 m おき。屋根の高さは当たり判定から取る。中庭の範囲・門の外の位置も `SITE`（`data/appearance.json` のグランシティの値から手で写した。グランシティの形を変えたら合わせる）。
- 確認: `node tools/dev/swarmcheck.js <出力フォルダ>`（何もしないとやられて門の外へ戻るか・近い敵へ攻撃を連打して何体倒せるか・着地点が中庭の中か・受けるか聞く表示の Y / N / ボタン / 中庭から出たら閉じるか、と画面 4 枚）。見た目だけなら `tools/dev/swarmview.html`。

### 神社の社殿（八坂神社。tools/shrine.py・public/src/shrine.js）
PLATEAU では灰色の窓付きの箱だった八坂神社（旧東海道沿い）の社殿を、写真と点群から作り直した。
- 設定は `data/appearance.json` の `shrines`（位置 `origin` = 屋根の中心、正面の向き `facing`、屋根・身舎の寸法 `hall`、北西の小屋 `annex`）。位置・向き・高さは点群（`fetch_lidar.py`）と航空写真（`fetch_ortho.py`）から測った: 境内は道路より約 2.9 m 高い、屋根は正面の幅 6 m・奥行き 6.8 m・棟 5.9 m・軒 3.4 m、正面は東から 17° 南（旧東海道の鳥居と石段の方）。
- 外観（`shrine.js`）は Wikimedia Commons の写真（正面・鳥居の下から）から: 銅板葺き（緑青）の入母屋・平入りの屋根、正面に向拝（柱 2 本・しめ縄と紙垂・鈴と紅白の鈴緒）、焦げ茶の板壁と格子戸、高床の浜縁と木の階段、コンクリートの基壇、三つ巴の金具の賽銭箱。北西の赤い屋根の小屋は PLATEAU に無いので足した（点群と写真から。形は推定）。裏・横の面は推定。
- 仕組み: `tools/shrine.py` が PLATEAU の建物に `"hide": "shrine"` を付ける（建物は消さない。ミニマップには輪郭が残る）。`main.js` は hide の建物を街の形と当たり判定から外し、`build_props.py` はベランダ・看板を付けない。`build_props.py` が `props.json` の `shrines` に地面の高さと当たり判定（基壇・浜縁・身舎・柱・賽銭箱・小屋）を書き、`shrine.js` が描く（小物の表示 V キーに関係なく出す）。
- 参道（`approach`）: 点群から、歩道の外の縁で 2 段上がる石の踊り場（奥行き約 3.4 m）に石の明神鳥居、9 段の石段（両脇にステンレスの手すり）、両脇と道路側は間知石の石垣、上に石畳。石段の筋は社殿の中心線より 0.6 m 左。踊り場と上の石畳は、ゲームの地形（2 m 間隔でなめらか）が上に出ないよう、実測より 0.15〜0.3 m 高い。段は当たり判定の箱（乗れる）で、階段として登録している（上り下りの姿勢。`stairs.js` の `addStair()`）。OSM の石段（歩道を横切っていた）は `hide_roads` で描かない（手すりも付けない）。
- 境内の小物（`items`）: 写真に写っている狛犬（石段の上の両脇。阿吽）・手水舎（緑青の切妻屋根・水盤）・石灯籠（火袋が夜に光る）・町内会の掲示板・石の車止め・踊り場の石と、OSM の点の石碑（明治天皇東幸史蹟・庚申塔・歌祭御大詠）・案内板（由来・お札まき）。位置は社殿の局所座標か地図の位置（`world`）、高さは `level`（踊り場・石段の上）か地形。形は簡略（狛犬は丸と筒の組み合わせ）。当たり判定あり。
- お祭りの飾り（`festival`。推定。写真には無い）: 赤と白の提灯の列（石段の両脇と、社殿の前と両脇（お札まきの舞台を囲む）。柱の間の縄に約 0.85 m おき。`InstancedMesh`）と、鳥居の両脇の幟。提灯と石灯籠は夜に光る（材質を `built.windowMats` に入れ、`time.js` が明るさを決める）。北の広場の列は、以前の舞台のカメラをさえぎらない向きに置いたもの。
- ガードパイプの切れ目（`build_props.py` の `near_walk_end()`）: 歩行者の道（歩道・階段・小道）が横から車道に出る所は、その側のガードパイプを切る（車道に沿って走る歩道の区切りは切らない）。以前は八坂神社の石段の下をふさいでいた。街全体で 38 か所・支柱 83 本が減った。
- 実行: `python tools/shrine.py`（`build_props.py` も実行する。何度実行しても同じ）、`--undo` で hide を外す。`build_city.py` からも呼ぶ（通しでは未確認）。PLATEAU を取り直して建物の ID が変わったら `shrines[].hide` を直す。

### イベント「リズム地獄(八坂神社)」（旧称: お札まき 合いの手。public/src/rhythm/）
八坂神社（旧東海道沿い。戸塚の八坂神社には、うちわを手に歌い踊ってお札をまく祭り「お札まき」がある）の境内に入ると、参加するかを聞く（**Y** / Enter / 「はい」、**N** / 「いいえ」。断ったら、境内の外へ出て入り直すとまた聞く）。始まると、社殿の前で手本役（赤い上着の人）と向かい合い、両脇に見物人が並び、カメラは自分の右後ろからの固定になる。リズムゲームの 1 曲（約 30 秒）。
- 遊び方: 手本役が 1 小節うちわで打って見せ（太鼓の音）、次の 1 小節で同じリズムを返す。手本は 3 拍目までで、4 拍目に「はい！」の合図（文字と、拍子木 2 つの音）が出て、そこから次に返す升目が先に見える。次に打つ升目には金の輪が出て、打つ瞬間に向けて縮む（音が出なくても打つ時刻が分かる）。打つのは **Space** / **J** / **クリック**（スマホは画面のどこでもタップ）。ボタンは 1 つだけ。
- 曲（`event.js` の `SECTIONS`・`POOLS`）: テンポ 107・20 小節（約 45 秒。持ち主の指定）。前奏（太鼓 4 つ）→ うちわ打ち（手本・返しを 2 回）→ お札まき（裏拍が入る。うまく打つとお札が舞う）→ 速い 4 小節（`rush`。1 小節に 4〜5 打）→ 伴奏（拍子木）が止まる（返す小節は伴奏も今の位置の印も無い）→ ラスト（`rush` を 1 回）→ 締めの一打（手本役といっしょに。お札が大きく舞う）。手本の打ち方は毎回、候補から選び直す。返す拍は 30 台半ば。
- 判定（おみくじ）: ずれ ±0.07 秒で「大吉」（内部では good）、±0.13 秒で「吉」（ok）、外れたり打たなかったりで「凶」（miss。早い・遅いを添える）。音も 3 種類（大吉 = 鈴が上がる、吉 = 鈴 2 つ、凶 = 低い「ぼよん」。`audio.js` の `daikichi`・`kichi`・`kyo`）。拍から 0.25 秒より離れた打ちは「×」（数えない）、0.25 秒以内で外れたら近い拍のミス（連打でごまかせない）。打った時刻はキー・クリック・タップの瞬間（`ev.timeStamp`）で取るので、1 コマの長さに左右されない。**ずれ合わせ（遅れの測定）は無い**（持ち主の希望）。代わりに判定の幅を広めにし、ブラウザが知らせる出力の遅れだけ自動で差し引く（`audio.js` の `now()`）。Bluetooth のイヤホンは遅れを知らせないことが多く、ずれて感じる。
- 結果: 良 = 1、可 = 0.6 の割合で、0.85 以上「大吉！」、0.55 以上「吉」、それ未満「凶…」。大吉・吉・凶の数。**Y** でもう一回、**N** でやめる。曲の間はその場から動けない（R・地図のワープ・地図を開くと中止）。
- 舞台（2026-11 に移した）: 鳥居をくぐって石段を上がってすぐの、社殿の正面。手本役は社殿の前（社殿の中心から正面へ 5.8 m）、自分はそこから石段側へ 4 m（9.8 m）、参道の筋の上。位置は社殿の局所座標から `rhythm/event.js` の `SITE`（`W()`）で計算する。見物人は両脇 3.4 m、うな○ーはその外側（`SITE.fans`）。
- 締めの一打（大吉・吉）で、うな○ー・見物人・手本役が全員いっせいに跳ぶ（0.85 秒。うな○ーは万歳、着地でつぶれて土ぼこり。`unaa.js` の `jumpAll()`・`jumpY()`）。自分は跳ばない。
- 凶のとき、うな○ーがいれば、舞台に近い 3 体のうち 1 体が自分へ走ってぶつかり（どすんの音、水玉）、しょんぼり元の場所へ帰る（約 2 秒。`unaa.js` の `charge()`）。ぶつかっても自分の動きは変わらない（見た目だけ）。
- 自分のキャラの動き（かわいく。`character.js` の `festPose()` の `fan`、渡す値は `event.js` の `perfAct()`）: ①拍の頭で膝を曲げ、体と首を左右に揺らす（盛り上がるほど大きく）。②打つと跳ぶ（大吉 0.3 m・吉 0.12 m。跳んでいる間は右足を蹴り上げる。高さと回転は `player.js` の `show()` が root へ足す）。③大吉は 1 回転して左手を上げて万歳、吉はうなずく、凶はしょんぼり（肩を落とし、首を振り、膝を内へ）、うな○ーにぶつかられるとのけぞって両手をばたばた。
- 舞台のまわり: 提灯の列を社殿の前（社殿の手前の横一列）と両脇に移した（`data/appearance.json` の `festival`）。カメラは自分の後ろ 4.2 m・上 3.2 m・参道の筋の左へ 1.5 m（`SITE.cam`）。舞台の範囲にある木（幹と枝が画面をさえぎる）は、曲の間だけ消す（`hideTrees()`。終わると戻る）。
- 大吉のたびに、観客へ「うな○ー」が（大吉で 3 体、吉で 1 体）ずつ空から降りてきて加わる（`rhythm/unaa.js`。`swarm/model.js` の見た目を再利用。最大 90 体、舞台と見物人の列のまわりの格子 `SITE.fans`、足りなくなったら少しずらして重ねる。曲に合わせて跳ね、盛り上がりが高いほど高く跳ぶ。曲の始め・終わりで消える）。
- 画面: 上に 8 つの升目（1 小節を 8 分音符で分けた位置）。手本の小節は手本役が打った所が赤く光り、返す小節は打つ所に白い枠、打つと運勢の短冊になる（大吉 = 金で「大吉」・吉 = 白で「吉」・凶 = 灰で傾いて「凶」。縦書き）。升目はおみくじの短冊の形。音が出ない（消音・iPhone の消音スイッチ）ときも、升目と手本役の動きで遊べる。
- 音（`audio.js`）: iPhone は消音スイッチ（マナーモード）が入っていると Web Audio の音を消すので、音楽の再生と同じ扱いにして鳴らす（`navigator.audioSession.type = 'playback'`、古い iOS 向けに無音の `<audio>` を 1 回再生）。曲の始めに音の準備ができていなければ最大 1.5 秒待ち（`AUDIO_WAIT`。画面は「準備中…」）、それでも出なければ音なしで始め、画面の下に「音が出ていません」と出す。太鼓・うちわ・拍子木・鈴・歓声・空振りを、音のファイルを使わずブラウザの中で合成する（Web Audio）。曲の音は始めたときにまとめて予約する。ブラウザはページを触った後でないと音を出せないので、どこかを触った瞬間に使えるようにしている（ゲームの開始のクリック・タップで済む）。人の声（掛け声）は無い（文字で出す）。
- 動き（`character.js` の `festPose()`）: `fan` = 右手のうちわを頭の上に構え、打つ瞬間に前へ振り下ろす（締めの前は高く掲げる）、`cheer` = 見物人が両手を上げて弾む（うまく打つほど盛り上がる）。うちわは右手に付く板（`fan`）。手本役と見物人は組み立て式のキャラ（手本役はいつも境内に立っている。見物人は曲の間だけ）。
- 自分の画面だけの出来事（マルチプレイのほかの人には見えない。動きの番号も送らない）。URL に `?norhythm` で無効、`?rhythm` で開いてすぐ境内で聞かずに始める、`?rhythm=auto` でさらに自動で打つ（確認用）。撮影（`?shot`）では `?rhythm` が無ければ始まらない。
- 確認: `node tools/dev/rhythmcheck.js <出力フォルダ>`（時計を差し替えて打ち方ごとの結果・結果からもう一回 / やめる・本物のキーとタップ・聞く表示、と自動で打つ画面 5 枚）。

### イベント「プロジェクトセマイ ワンルームステージ！」（旧称: ゲームセンター リズムステージ。public/src/arcade/・public/arcade/・tools/music/）
戸塚駅西口の路地にある赤いゲームセンター（タイトーステーション 戸塚西口店。外観は「外観設定」の `taito_station`）の入口に少しとどまると「入りますか？」と聞く（Y / Enter / ボタン）。はいで画面いっぱいのゲーム画面（街の描画は止まる）。プロセカのような 6 レーンのリズムゲームで、パステルでかわいい見た目（マスコットの「ぽよ」、水玉・星・ハートの背景、サビで光の筋、大サビで虹色）。自分の画面だけの出来事。
- **曲（5 曲）**: 歌入りの 4 曲（フリーボーカルMusic【NeWorld】の「ぴぴぴ☆受信ちゅう！」「ミライミライ」「おかえり、ただいま」「soap bubbles」。作詞・作曲 R2、歌 aya）と、自作のインスト 1 曲。曲の一覧は `public/arcade/songs.json`（`python tools/music/make_songs_index.py` が作る）。曲えらびの画面で選ぶ。曲ごとの譜面と音は選んだときに読み込む。NeWorld の曲は音楽利用のルール（無料・商用 OK・ゲーム OK・クレジット表記・音楽だけの再配布は禁止）に従って使い、**曲えらびと曲の最中の画面の下にクレジット**（「音楽：フリーボーカルMusic【NeWorld】…」と URL）を出す。曲のファイルは `public/arcade/<id>.mp3`（160 kbps に直したもの。元は wav を作業用フォルダにだけ置き、git には入れない）。規約は予告なく変わることがある
- **歌入りの曲の譜面**: 楽譜が無いので、音から自動で作る（`python tools/music/audio_chart.py <wav> --id <id> --title "…" --credit "…"`。`pip install librosa soundfile` が要る）。立ち上がりの検出（自作曲で測った約 10 ms の遅れを補正）・拍の列（開始テンポを変えた多数決 + 位相の細かい合わせ込み）・歌の高さ（歌の帯域だけを残した pyin。レーンは選んだ音の分布の 6 等分）・長押し（高さが 1 半音以内で続く長い音）・フリック（上へ 5 半音以上跳ぶ所）・区間（小節ごとの音の大きさ。4 小節より短い区間は前に合わせる）。密度は NORMAL 約 2.2 個/秒・HARD 約 4.4 個/秒（1 秒の上限 5 / 8 個）。機械的な推定で、遊んで直す前提
- **自作のインスト**: オリジナル（歌なし。BPM 172、Bの終わりで 140 → 92 に落として、サビから 200）。`python tools/music/song_pop1.py <フォルダ>` が合成して `song_pop1.wav / .mp3 / .json` を作る（numpy と ffmpeg。乱数は固定で、何度でも同じ曲）。mp3 は `public/arcade/song_pop1.mp3`（約 2MB）に置く
- **自作のインスト曲の譜面**: `python tools/music/make_chart.py <フォルダ> --public` が、曲の旋律から NORMAL（213）と HARD（352）を作って `public/arcade/chart.json` に書く（`--png` で一覧画像）。旋律の高さがレーン（低い音 = 左）。タップ / フリック（上へはじく）/ 長押し。決まりは `make_chart.py` の先頭
- **操作**: キーボード S D F J K L（左から）。スマホ・タブレットは画面のレーンをタップ・長押し・上へはじく。Esc または左上の ✕ でやめる。ゲーム画面の間、キャラ・扉・ほかのイベントには入力を渡さない（main.js の `NOIN`）
- **判定**（`game.js`。±秒）: PERFECT 0.045 / GREAT 0.09 / GOOD 0.135 / BAD 0.18、外れるとミス。PERFECT・GREAT・GOOD でコンボがつながり、BAD・ミスで切れる。点 = 判定の重み（1 / 0.8 / 0.5 / 0.2 / 0）の平均 × 100000。ランク S 92000〜 / A 80000〜 / B 60000〜 / C。長押しは最後まで押し続ける（早く離すとミス・点 0.3 倍）。指で触る人のフリックは、押してから 26 px 以上上へはじく（はじかないと GOOD まで）。キーボードは押すだけ
- **時計**: 曲は Web Audio で鳴らし（`rhythm/audio.js` の `startSong`）、判定の時計は音の出力の時刻（`now()`）に合わせる。入力は `ev.timeStamp` で判定（1 コマの長さに左右されない）。曲えらびの「タイミング」（±10 ms 刻み）で端末ごとのずれを直せる。設定（難易度・速さ・効果音・タイミング）とベストはブラウザに覚える（`localStorage` の `arcade.v1`）
- **判定・ノーツの色・オーロラ・レーンをまたぐ長押し**: 判定は少し甘め（perfect ±0.06 / great ±0.115 / good ±0.17 / bad ±0.22 秒。`game.js` の `WIN`）。ノーツの色はレーンでなく種類で決まる（押す = ピンク、フリック = 金の星、長押し = 水色。`draw.js` の `TAP_COL` など）。押した瞬間は、判定線から立ちのぼるオーロラ（`aurora()`・`drawAuras()`。加算合成の帯を色をずらして重ねる。完璧ほど高く、種類で色あいが変わる）と、星・ハート・音符の散らばり。長押しの間も、ときどき小さなオーロラ。長押しには途中でレーンをまたぐもの（譜面の `via: [[時刻, レーン], ...]`）があり、時刻の前後 0.25 秒のうちに移る先のレーンを押す（キーなら新しいキーを押す。指なら長押しのまま指をとなりへすべらせる。元のレーンを先に離してもよい）。間に合わないと失敗。リボンは斜めに移る。`tools/music/add_slides.py` が譜面の後処理で、長押しを少し増やし（次のノーツまで 1 秒近くあいた「押す」を拍にそろえた長押しに置き換える。ノーツ数は変わらない）、レーンをまたぐ指定を足す（移る先のレーンにほかのノーツが無い所だけ。譜面に `slides: true` の印を付け、2 回目は何もしない。譜面を作り直したらまたかける）
- **曲ごとの背景**（`scenes.js`。曲の id → 場面。無い曲はいつもの水玉と星）: `pipipi`（アンテナ・綿あめの雲・虹）、`miraimirai`（夜明けの光の輪・未来の街・光の道）、`okaeri`（夕焼け・家並みの窓に明かりがともる・カラス）、`soap`（シャボン玉がのぼり拍で割れる）、`pop1`（ネオンの太陽・イコライザー・流れるグリッド）。共通の `SceneBase` が時計・サビの熱さ（`cf`）・拍の弾みを用意し、サビで色・数・速さが変わる。絵は素材を使わず canvas で描く。曲を足すときは場面のクラスを作って `SCENES` に登録する
- **レーンのうねりと疾走感**（`draw.js` の `updateFx`・`cxAt`・`drawStreaks`）: レーンが拍に合わせて左右にうねる（8 拍で 1 回り。テンポが変わっても曲に合う）。うねりの大きさは判定線で 0、奥ほど大きい（**打つ位置・ノーツが降りる速さ・タッチの判定は変わらない**。見た目だけ）。波は判定線へ向かって進む。区間の勢い（intro 0.25 / A 0.4 / B 0.6 / chorus 1.0 …）で、うねりの大きさ・疾走線（レーンの上を手前へ流れる光の線）の数と速さ・背景の流れの速さ・奥の狭さ（遠近）が変わる。長押しのリボンもうねりに沿って曲がる。HARD は小さめ（×0.75）。曲えらびの「レーンのうねり」で なし / ふつう / おおきく（0 / 1 / 1.7）。OS の「視差効果を減らす」設定の人は、最初は「なし」
- **画面**: `draw.js`（canvas。絵は最初に 1 度だけ作る）。拍に合わせて背景・マスコットが弾み、区間ごとに背景の色が変わる。曲えらび・結果は HTML（`index.html` の `#ar-*`、`style.css`）
- **URL**: `?arcade` で開いてすぐ曲えらびへ / `?arcade=auto` で自動で打つ（`&diff=HARD`、`&bot=0.15` で 15% を打たない）/ `?arcade=ask` で入口に立つだけ / `?noarcade` で無効。確認用の `tools/dev/arcade_test.mjs`（判定・点数。node だけ）、`arcadeshot.js` + `arcadeview.html`（画面だけを素早く撮る）、`arcadecheck.js`（ゲーム本体での通し。ask → 曲えらび → 入力 → 結果、スマホのタッチ）
- 地図の印: 入口の前に「！」（ピンク）。最中は点滅

### イベントの場所の印（public/src/eventmarks.js）
ミニマップと大きい地図（M）に、イベントの場所を色付きの丸に「！」の印で出す（うな○ーのクエスト = 緑、お札まき = 赤）。ミニマップは見えている範囲にあるときだけ（縁には貼り付けない。持ち主の希望）。大きい地図は名前つきで、印をクリック（スマホはタップ）するとそこがワープ先に選ばれる（`bigmap.js` の `pickAt()`。あとはいつものワープ）。イベントの最中は印が点滅し、外側に輪が出る。一覧は `main.js` の `EVENTS`（各イベントの `SITE` から作る。イベントを足すときはここに 1 行。`?noswarm` などで無効にしたイベントは出さない）。
