### 光と空気感（public/src/look.js）
街のデータには手を入れず、描き方だけで質感を上げる。5,600 棟すべてに自動で効く。
- 空の映り込み: 空のシェーダ（太陽の円盤は消す）をぼかして `scene.environment` に入れる。時間帯が変わると作り直す。強くすると日陰が明るくなって影が消えるので、弱め（昼 `envI` 0.1）にし、半球ライトを 8 割に下げて合わせている
- かすみ: 霧を距離に応じて指数的に濃くする（80 m 先から。250 m で約 11%・600 m で約 29%）。`THREE.ShaderChunk.fog_fragment` を差し替える
- 物の陰（AO）: three.js の GTAO を半分の解像度で。法線は深度から復元するので、街を 2 回描かない
- にじみ（ブルーム）: 夜の窓・看板・街灯が光ってにじむ。昼は弱い
- 色の仕上げ: 露出 → ACES → 彩度・コントラスト（sRGB で掛ける）・周辺減光
- 時間帯ごとの強さは `time.js` の `envI`・`hemiK`・`ao`・`bloom`・`bloomT`・`sat`。URL で上書きできる（`?envI=0.2&aoK=0.8`）
- スマホ・タブレットは映り込みとかすみだけ（AO・にじみ・色の仕上げは画面の大きさの描画先を何枚も使うのでメモリを食う）。`?post` で使える
- 切り分け: `?plain`（全部なし = 以前の見え方）、`?noao`、`?nobloom`、`?noenv`。撮影は `node tools/dev/shot.js <出力> <視点> --q '&plain'` で以前の見え方

### 空と時刻（public/src/skyfx.js・time.js）
空は three.js の `Sky` のシェーダを土台に、`skyfx.js` が中身を置き換え・書き足している。追加の描画・テクスチャは無く、1 枚のシェーダで描く（スマホでも使える）。
- **大気**: 空の色は単散乱の大気モデル（レイリー + ミー + オゾン。1 画素あたり視線上 14 点）。太陽までの光の減り方は、起動時に JS で作る表（`buildTransmittance()`。256 × 32 の半精度の画像。横 = 太陽の高さ、縦 = 高さ）を引く。地球に隠れる向きは光が届かない。昼は青い天頂と白い地平線、日没は黄 → 橙 → 赤の地平線と上の紫・藍、日没後は地球の影で暗くなる（以前の Preetham 式は夕方がくすんだ緑がかった青で、赤が出なかった）。太陽の円盤も大気で赤くなる。定数は `skyfx.js` の `uSkyI`（明るさ 28）・`uMie`（かすみの量。天気で使う）・オゾン 2.5 倍（藍を出す）。**単散乱なので、多重散乱の分（日陰の空の明るさ）は足りず、日没後の空は薄明の手づくりの帯（`tw`）と夜の空へ混ぜて補っている**
- **雲**: 3 層を、視線と水平な面の交点から作った座標で fbm ノイズにして重ねる。高い巻雲（薄い筋）・中ぐらいの高積雲（小さなむら）・低い積雲（大きい、陰がある）。陰は、光の向きへずらした点との濃さの差から付ける。縁は光が透けて明るく、太陽の近くは銀色に輝く。色は太陽の高さで変わる（昼は白、日没は橙、日没後は紫・紺、夜は月明かりの青灰色）。風でゆっくり流れる。量は `cloud`（0〜1。時間帯ごとの値は `time.js`）
- **夜空**: 星（2 段階の大きさ・色温度・またたき）、天の川（星の多い帯）、月（満ち欠けと模様つき）。星空は天の北極（北緯 35.4°）のまわりを回る。月齢は実際の日付から計算（`moonPhase()`。新月 = 0、満月 = 0.5）。月は太陽から月齢ぶん遅れて同じ道を通る（満月は真夜中に高く、昼は沈んでいる）。夜の光（影の向き）も月の向きに合わせる（低すぎるときは高さの下限あり）
- **薄明**: 日の出前・日没後の、地平線の赤〜紫〜紺の帯（太陽の向きがいちばん強い）。地平線の空は霧の色（`scene.fog`）に溶かし、遠くの建物と空の境目をそろえる。夜の空の色も霧の色から作る（以前は夜だけ紺色一色の背景だった）
- **時刻は連続**: `time.js` の `hour`（0〜24）。太陽は 6 時に東から出て、12 時に南で最も高く（56°）、18 時に西へ沈む。光の色・強さ・明かり（窓・看板）・露出などは、時刻ごとの見本 `KEYS`（夜・夜明け・朝・昼・夕方・夕焼け・夜）の間をなめらかにつなぐ。T キー・時間ボタンは次の時間帯の時刻（昼 12・夕方 17.6・夜 22・朝 6.8）へ**時間を進めて**向かう（夜 → 朝は 0 時をまたぐ。1 秒ほどで日が沈む・昇る）。画面の時刻表示は「昼 12:00」のように時刻つき
- **URL**: `?hour=17.5`（始める時刻）、`?tspeed=30`（時間を流す。1 分で何時間進むか。T で時間帯へジャンプしても流れ続ける）、`?cloud=0.8`（雲の量）、`?moon=0.5`（月齢）
- **映り込み**: 空の映り込み（`look.js`）は雲だけ入れ、星・月は描かない（`#define SKY_DISCS 0`。小さくて明るい点がぼけて光るため）。映り込みは太陽が 1° 動くごとに作り直す
- 確認: `node tools/dev/skycheck.js`（11 項目: 全時刻で値が有限・なめらか、T で昼 → 夕方 → 夜 → 朝、時間の流れ、月・星の向き、シェーダのエラー無し）。空だけを数秒で撮る `tools/dev/skyview.html`（`node tools/dev/charshot.js out "hour=18&yaw=-90&pitch=8&skyline=1" --page skyview`。先頭のコメント）
- **未対応**: 雲の影が地面に落ちる表現、天気（雨・霧・曇り）、雲の中の光の通り抜け（簡易な陰影）、星座・実際の星の位置（星は乱数）、日食・月食、水面への空・月の映り込み、季節による太陽の高さと日の長さの変化（いつも春分・秋分の 6〜18 時）

### 木の見た目（葉の板・樹形・葉の色。`public/src/trees.js`・`tools/tree_traits.py`）
木の位置・高さは点群の実測（上の「空き地を埋める」の `lots.json`）。見た目は 3 つの層で作る。
- **葉の板**（`trees.js`）: アルファ抜きの小さな葉の模様（256 px に 240 枚ほど。先のとがった葉・針葉）を貼った板を、樹冠の形に 50 枚ほど重ねる（幹には枝も付く）。近く（85 m 以内、スマホは 50 m）だけこの形で、それより遠い木は 20 面ほどの簡単な形に入れ替える（カメラが 15 m 動くたびに `TreeLayer.update()`）。遠くで葉が消えないよう、模様の面積の 6 割ほどを葉で埋め、アルファの判定を 0.3 に下げた。URL に `?simpletrees` を付けると、以前の簡単な形（正二十面体）に戻る。
- **種類と幅**（`tools/tree_traits.py` → `data/tree_traits.json`）: 木の中心から 1 m ごとの輪の高さ（点群の格子）で、樹冠の半径と「円すい度」（半径の半分の所の高さ ÷ 頂点）を読み、広葉樹（丸い）・針葉樹（円すい。円すい度 < 0.62・幅/高さ < 0.3）・細い木（幅/高さ < 0.2・高さ 7〜16 m）・低木（高さ 3.2 m 未満）に振り分ける。幅は基準の木（半径 1.7 m / 高さ 4.9 m）との比（0.6〜1.5）。
- **葉の色**: 木の中心の周りの航空写真の、緑が勝つ画素（暗い側 30%・明るい側 10% を除いた中央値）。写真は彩度がほぼ 0 なので、全体の 5〜95 パーセンタイルを葉らしい色相・明るさ・彩度に引き伸ばし、木どうしの違い（黄緑・濃い緑・日陰）だけを使う。緑が 15% に満たない木（屋根・舗装の上）は読まず、乱数の緑にする。
- `build_props.py` が `props.json` の `trees` を `[x, z, y, 高さの倍率, 乱数, 葉の色 (0xRRGGBB か null), 種類, 幅の倍率]` にする（壁に近い木は横を細く・低くする。`tree_traits.json` が無いときは先頭の 5 つだけで、全部広葉樹）。`python tools/tree_traits.py`（`--undo` で消す、`--sheet <png>` で種類ごとの航空写真の見本）。点群の「木」には建物の縁・屋根の上の物・車も混ざる（航空写真と並べて確かめた）ので、種類を細い木・針葉樹にした木のうち半分ほどは木でないものを読んでいる。木の数は変えない。
- イベントで木を消す（お札まきの舞台）は `TreeLayer.hide()`・`showAll()`。
- **ほかの場所の木**（同じ `TreeLayer`。層は作ると登録され、`main.js` が毎コマ `updateTreeLayers(camera)` で全部の近い / 遠いを入れ替える。`new TreeLayer(spots, 名前, { gain })`）: パークの丸い木・桜・松（`detail/parkareas.js`。倍率は基準の木との比、色は設定のパレット、`gain` 1.3 = 明るい配色が葉の影で沈むのを上げる。やしの木・枯れ木・棒つきキャンディの木は作り物の形のまま）、舞浜駅前の木（`detail/stationsite.js`）、敷地の庭の円すい形の庭木（`detail/site.js`。針葉樹）。**まだ以前の簡単な形**: 線路の延長部分の木（`detail/railext.js`。区間ごとに作る・位置は決まりで散らしたもの・本数が多い）。`?simpletrees` は街の本体とパークだけ以前の形に戻す

### 街並みディテール（お試し中・スタート地点の半径250m）
ゲーム内は V キーでまとめてオン/オフ。段階ごとの有効/無効は `public/src/detail/config.js`。
配置の計算はすべて `tools/build_props.py`（`props.json`）。`public/src/detail/` は形を作って置くだけ。
1. 路上の小物: 電柱・電線・街灯・横断歩道・停止線と「止まれ」・ガードパイプ・自販機・カーブミラー（道路データから自動配置）
   - 信号機・バス停（`public/src/detail/street.js`）: OSM の信号（`highway=traffic_signals`）の交差点に、横型3灯の車両用信号（左側・横断歩道の先・車道へ張り出す）と、横断歩道の両端に歩行者用信号を置く。青22秒→黄3秒→全赤2秒で縦横が交互に切り替わり、歩行者用は青の終わりに点滅。単路の押しボタン式（`crossing=traffic_signals`）は横断歩道も描く。バス停（`highway=bus_stop`）は最寄りの道路の縁に、丸い標識・停留所名の板・時刻表を置く
   - 位置は `city.json` の `streetNodes`。無い（古いデータの）場合は `pois` の名前付きの信号・バス停だけを使う。名前の無い信号も出すには `fetch_osm.py` → `build_city.py` を実行し直す
   - 配置の計算は `tools/build_props.py`（以前はブラウザで毎回計算していた）。ブラウザは `props.json` を読んで置くだけ。Unity でも同じデータを読む
2. 素材テクスチャ: Poly Haven の CC0 素材（`python tools/fetch_detail_textures.py` で取得）を道路・歩道・外壁・屋根に重ねる
   - 壁と屋根の材質（`detail/textures.js`。番号は `city.js` の `WALL_MAT`・`ROOF_MAT`、頂点の `matId`）: 建物ごとに自動で選ぶ（`pickWallMat`・`pickRoofMat`。種類・高さ・壁と屋根の色から。日本の街でよくある組み合わせの推定で、1 棟ずつ実物とは照らしていない）
     - 壁: 吹き付け（写真の模様）／横張りのサイディング（455 mm の板・3,030 mm の継ぎ目）／タイル（写真の模様）／打ち放し（型枠の目地・セパ穴）／角波の鋼板（200 mm のひだ）／ALC（600 mm の目地）。戸建ては多くがサイディング、茶系のマンションはタイル、工場・倉庫は鋼板か ALC
     - 勾配屋根: スレート（200 mm の段・910 mm の継ぎ目）／瓦（305 mm の波・235 mm の段・つや）／金属の立平（455 mm のはぜ・金属のつや）。色で選ぶ（青・緑・明るい灰色は金属、黒・濃い灰色は瓦かスレート、茶はスレートが多め）
     - 段・目地・波は凹凸（法線）としても描くので、日の向きで陰が出る。写真の凹凸（法線の画像）はスマホでは使わない（メモリ）
     - 窓（壁の模様の青い所）はガラスとして空を強く映す（`uGlass`）
     - 細い線は画素の幅でぼかし、周期が画素に近づくと消す（遠くでちらつかないように。`fwidth` は分岐の外で求める。分岐の中で求めると白い点が出た）
   - 地面（`patchGround`）: 車道に補修跡（新しいアスファルトの黒っぽい塊）・ひび割れ（古い所だけ）・汚れのむら、歩道に汚れのむら。位置は値ノイズ（512 m で繰り返す）
   - マンホール（`props.json` の `manholes`、車道の中に約 25 m おき。下水の丸い鉄蓋と小さな蓋）と側溝（`gutters`、歩道の無い生活道路の両端。コンクリートの蓋と 5 m に 1 枚のグレーチング）。位置は `build_props.py`、模様は `detail/props.js` の Canvas
3. 建物の作り分け: 戸建ての切妻/寄棟屋根、集合住宅の南向きベランダ、店舗・病院の看板と日よけ

### 撮影モード（public/src/photo.js・touch.js・style.css の `body.photo`）

端末のスクリーンショットで景色を撮るために、画面の部品を全部消す。撮影そのものはアプリにはない。
- 入る: I キー / メニューの「撮影モード」 / スマホの上の帯の「撮影」。電車・観覧車に乗っている間、メニュー・地図・修正モード・イベント（うな○ー・お札まき・ゲームセンター）の最中は入れない。
- 消すもの: `#app`（街の絵）と `#photo-ui` 以外の `body` 直下の部品を CSS で全部消す（ミニマップ・メニュー・地名・案内・出典・スティック・ボタン・地名ラベル・ヘルプ・マルチプレイの表示など）。新しい画面の部品を足しても、`body` 直下に置けば自動で消える。
- できること: ズーム・視点。ズームの上限は撮影中だけ 30 m → 80 m。PC は `T` で時間帯も変えられる。人と車の更新は止まる（`main.js` が `crowd.update`・`traffic.update` を呼ばない）。キャラへの入力（攻撃・扉など）は渡さない。
- 抜ける: 歩き出す（WASD・矢印・Space・Shift・スティック）・Esc・I（PC。入る前から押していたキーでは抜けない = `armed`）。PC でマウスの固定が外れたときも抜ける。スマホは、画面を動かさずに 1 回タップすると右上に「× 撮影モードを終わる」が 3 秒出る。入った直後に 3.5 秒だけ案内が出る。何も触らなければ何も写らない。スマホは画面のどこをドラッグしても視点（スティックは出ない）。
- 確認: `node tools/dev/photocheck.js <出力フォルダ>`（PC 19 項目・スマホ 11 項目。`PHOTO_ONLY=touch` でスマホだけ。ソフトウェア描画なので全体で 10 分ほど）。
