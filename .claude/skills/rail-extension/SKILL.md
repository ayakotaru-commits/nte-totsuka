# 線路の延長・駅を足す (rail-extension)

戸塚駅の地図 (x -650〜650, z -650〜1650。原点は戸塚駅付近、x = 東、z = 南、1 = 1 m) の外へ線路を延ばし、電車で行ける駅を足す。
2026-11 に東戸塚駅まで作った (段階 1 = 戸塚で乗り降り、段階 2 = 東戸塚まで延長、残りの作業 = 道路・木・坑口・地図)。続けて保土ケ谷駅まで延ばした (設定に 1 行足しただけ。貨物線の切り方と区の名前 `ward` を足した)。さらに横浜駅まで延ばした (1 つの駅に複数のホームを書けるようにした = `platforms`)。続けて東海道線で東京駅まで延ばした (舞浜までの計画の段階 2。川崎・品川・新橋・東京。`line_end`・`via`・ホームの `inner`/`only`・市の `city` を足した)。
段階 3a で、地図の中の道筋の続きではない **新しい線** (設定の `lines`。駅から始まる道筋) と **地下の区間** (トンネル・地下の駅) を足した。試しの区間は京葉線の東京 (地下のホーム) → 八丁堀。
段階 3b で京葉線を舞浜まで延ばした (越中島・潮見・新木場・葛西臨海公園・舞浜。**高架** = 設定の `viaduct`、地下から地上へ出る坑口と掘割、新しい線の `via`)。
仕組みの説明は README の「線路まわり」の「電車に乗る」「線路の延長」。ここには、**次に駅を足すときの手順と注意点**だけを書く。

## 全体の流れ (データ → 画面)
1. `data/rail_ext_config.json` (設定): どちらの端から延ばすか (`edge`: north / south)、駅 (`stations`)、最後の駅の先の長さ (`beyond`)
2. `python tools/rail_ext.py` → `data/raw/rail_ext_full.json` (全部入り。git に入れない) → 最後に `tools/rail_ext_split.py` を呼んで `public/data/rail_ext/` (`index.json` + 1 km 四方の区間 `c_<a>_<b>.json`) に分ける。分け直すだけなら `python tools/rail_ext_split.py` (数秒)
   - 線路: 国土地理院ベクトルタイル (`optimal_bvmap-v1`、z16) の **軌道の中心線 `RailTrCL`** (線路 1 本ずつ)。OSM はこの環境から読めない
   - 地図の中の道筋 (`props.json` の `rail.routes`、OSM 由来) の端の 15 m 内側の点を 1.5 m 以内で通る軌道を選び、外へたどる
   - 高さ: 標高タイル (DEM5A) + 0.55 m を均す。橋・トンネル (鉄道中心線 `RailCL` の `vt_railstate`) は両端を直線で、勾配は 2.5 % まで
   - 駅: 設定の緯度経度の近くで、止まる線 (`lines[0]`) の上下線 2 本の間に島式ホーム (長さ `length`、レールの上 1.0 m)
   - 周り: 線路から 350 m 以内の地形 (5 m)・PLATEAU の建物 (箱。横浜市・川崎市・東京都 23 区 = `PLATEAU_SRC`)・道路 (`RdCL`)・木 (決まりで散らす)、その外 2.5 km の粗い地形 (25 m)、架線柱、坑口
   - タイルの範囲: 地図の範囲と「地図の中心 → 駅 → 次の駅」の 1 区間ずつを囲む範囲 (まわり 1.5 km)。線路が駅と駅を結ぶ線から 1.5 km 以上離れる所があれば、途中に駅でない点を足す仕組みが要る (今は無い)
   - 線路のたどり方: 線の終わりで乗り移る。分かれ道では 2 km 先まで試しにたどって行き止まりを避け (`LOOK`)、設定の `via` の点の 1.5 km 手前からは最短のつながりでその点を通す
   - 新しい線 (設定の `lines`。段階 3a): 最初の駅の中心の 15 m 以内で、2 番目の駅の向きにそろった軌道の左 (下り = `out`。左側通行) と右 (上り = `in`) をたどる。最初の駅が終点 (`terminal`) なら、軌道の行き止まりから始まる。高さは、鉄道中心線が「地下」の所は地面から駅の `depth` m 下 (駅の間は直線で補間)、勾配は 3.5 % まで。地面がレールより 5.5 m 以上高い所はトンネルの中 (`ug`。壁・天井を描き、架線柱・坑口は置かず、地上の建物・道路・木をふさがない)。地下の島式ホームの駅は `spread` m まで上下線の間を広げる (国土地理院の地下の軌道は 2 本が約 5 m 間隔で描かれている)
3. 画面: `detail/railext.js` (地形・建物・道路・木・線路・坑口・駅。**区間はカメラから 3 km (スマホ 2.2 km) 以内だけ読んで作り、3.6 km (2.8 km) より離れたら捨てる** = `main.js` が毎コマ `detail.railExt.update(x, z)`。駅のホーム・当たり判定は最初から全部。地図の外の地形の高さを `terrain.js` の `setTerrainExt` に登録 (読み込んだ区間だけ)、`world.bounds` を広げる)、
   `detail/trains.js` (道筋に延長をつなぐ `joinExt`、止まる駅 `r.stops`、同じ道筋に複数の電車 `r.m`)、`ride.js` (乗り降り)、`minimap.js`・`bigmap.js` (`setExt` に `railExt.map` を渡す。全体の粗い絵 + 読み込んだ区間の細かい絵)

## 駅を足す手順
1. **駅の情報を調べる** (ja.wikipedia は curl で読める。`www.gsi.go.jp` は読めない):
   ```
   curl -s "https://ja.wikipedia.org/w/index.php?title=<駅名をURLエンコード>&action=raw" | grep -n "ホーム\|番線\|島式\|相対\|停車\|通過\|座標\|緯度"
   ```
   → ホームの形 (島式 / 相対式・面と線の数)、どの線が止まるか (例: 東戸塚は横須賀線だけ。東海道線・貨物は通過)、だいたいの緯度経度
2. **駅の位置を決める**: `python tools/rail_ext.py --find <駅名の一部> <緯度>,<経度>`
   → 注記 (駅名) と「駅部分」(鉄道中心線の駅の区間) の中央の緯度経度が出る。**「駅部分」の中央 (JR) を使う** (注記は駅舎・文字の位置でずれる)
3. **設定に書く** (`data/rail_ext_config.json`):
   - 同じ向きの先に足す (例: 東戸塚の先の保土ケ谷): その `extension` の `stations` の **後ろに** 足す (並びは地図の端から外へ)。`beyond` は最後の駅の先の長さ
   - 反対の端 (例: 南の大船): `{"edge": "south", "beyond": 700, "stations": [...]}` を `extensions` に足す
   - 駅: `{"name", "kana", "roman", "lat", "lon", "lines": ["yokosuka"], "platform": "island", "length": 310, "ward": "保土ケ谷区"}`。`ward` は画面の左上の区の名前 (駅から 400 m 以内)。横浜市でなければ `"city": "川崎市"` / `"東京都"`。`lines` の線名は `tokaido` / `yokosuka` / `freight`
   - ある線だけ手前の駅で切る: `"line_end": {"yokosuka": "横浜"}` (その駅の先 `beyond` m で切る。横須賀線は横浜の先で東海道線と分かれる)
   - **ホームが複数の駅** (横浜など): `"platforms": [{"line": "yokosuka", "type": "island"}, {"line": "tokaido", "type": "outer"}]`。`platforms` があれば `platform` は使わない。1 つずつ:
     - `island` = その線の上下線 (道筋 2 本) の間の島式 1 面 (間が 7〜20 m のとき)
     - `outer` = その線の上下線それぞれの外側 (反対の向きの線と逆の側) の、5〜20 m 先の平行な軌道 (国土地理院の `RailTrCL`。待避線など、道筋ではない = 電車は走らない) との間の島式 1 面ずつ (1 つで 2 面)。横浜の東海道線: 本線 6・7 番線は 4.5 m しか離れておらず、ホームは 5・6 と 7・8 の間
     - 任意: `length` (ホームの長さ)、`lat`/`lon` (ホームの中央。無ければ駅の位置)。道筋は駅の位置から 80 m 以内のものを探す
     - **どのホームにどの線が止まるかは Wikipedia の番線の表**で決め、**駅の中心で軌道を横に切った断面** (線路と線路の間の m) で、並びが表と合うか確かめる (横浜: 東から 3・4 京浜東北 | 5・6 東海道 下り | 7・8 東海道 上り | 9・10 横須賀、間 12.0・9.5・10.2・18.3 m。島式は 9〜20 m、隣のホームとの線路の間は 4〜6 m)。断面を出す小さなスクリプトは下の「はまった所」
     - `inner` = `outer` の反対 (反対の向きの線の側の隣の線路との間)。`only: "west"` (east / north / south) で上下線のうちその側の 1 本だけにする。品川: 上り 6 番線は `outer` の west (5・6)、下り 12 番線は `inner` の east (11・12)。東京: 上り 8 番線は `outer` の west (7・8)、下り 10 番線は `inner` の east (9・10)
     - 止まる位置はホームごとに、そのホームに接する道筋に付く (`outer` は 1 本ずつ)。`ride.js` は電車の中央からいちばん近いホームに結び付けるので、コードはそのまま動く
   - **線路が十数本並ぶ大きい駅で、正しい番線を通らないとき** (品川の下り線が 8 番線に入った): `"via": [{"line": "tokaido", "side": "east", "lat", "lon"}]` (extension に書く)。その線の上下線のうち `side` の側の道筋が、その点の 3 m 以内を通る線を通る。点は断面 (下の「はまった所」) で番線を読んで決める。`python tools/rail_ext.py --routes <json>` で道筋と駅だけを 30 秒ほどで作り直して確かめられる
4. **実行**: `python tools/rail_ext.py` (初回はタイル・PLATEAU・標高タイルを取るので数分。キャッシュは `data/raw/gsi_ext`・`data/raw/plateau`・`data/raw/dem`)
   出力で確かめる: 各道筋の `+◯ m` と `端のずれ` (2 m 程度まで)、`◯◯駅: ... 2 本の間 ◯ m` (島式なら 9〜15 m)、`注意: 同じ線路を通る` が出ないこと、`坑口` の数
5. **平面図で見る**: `python tools/rail_ext.py --plot <png>` (線: 東海道 = 橙・横須賀 = 青・貨物 = 灰、ホーム = 赤、坑口 = 黒丸)。線が途中で切れていないか、ホームが上下線の間にあるか
6. **ゲームで確かめる**:
   - `node tools/dev/ridecheck.js <出力> --station <駅名> [--line tokaido]` (30 項目。止まる線が複数の駅は線ごとに。**2 つ同時に動かすとブラウザが落ちることがある** (Target crashed)、20〜60 分。環境が遅いと 40 分の時間切れになるので timeout は長めに。戸塚 → その駅 → 戸塚の往復、ホームの上に立つ、縁から落ちない、など)
   - `node tools/dev/rideshot.js <出力> --station <駅名>` (ホーム・上から・途中・車窓の 4 枚、5〜10 分)。見て、持ち主に修正前後を送る
   - 準備: `mkdir -p tools/dev/.cache && cd tools/dev/.cache && npm pack three@0.170.0 -q && tar xzf three-0.170.0.tgz` (初回だけ)
7. README の「線路の延長」と docs/history/rail.md（CLAUDE.md には足さない）に、足した駅・確かめたこと・未確認のことを書く

## 新しい線を足す手順 (段階 3a で作った形。京葉線の東京 → 八丁堀)
1. 駅を調べる: Wikipedia でホームの形・深さ (地下の駅)。`python tools/rail_ext.py --find <駅名> <緯度>,<経度>` は地下の「駅部分」も出す (`駅部分 (JR・地下)`)。その中央を駅の lat/lon に
2. 設定の `lines` に 1 つ足す (書き方は `data/rail_ext_config.json` の `_doc_lines`): `id` (線名。`tokaido` などと重ならない)、`name`、`band` (帯の色 2 つ)、`cars`、`period`、`phase`、`dirs` (`out` = 最初の駅から外へ、`in` = その逆の行き先の表示)、`depth`、`beyond`、`stations` (`terminal`・`spread`・`depth`・`length`、ホームは `platform` / `platforms` で extensions と同じ)
3. `python tools/rail_ext.py --routes <json>` で道筋と駅だけを確かめる (1〜2 分)。出力の「上下線の間 ◯ m → ◯ m に広げた」「道筋 ◯ m・トンネルの中 ◯ m・レールの高さ」「◯◯駅: ... 2 本の間 ◯ m」
4. `python tools/rail_ext.py` → `node tools/dev/linecheck.js <出力> [--line keiyo]` (19 項目、約 25 分)。既存の駅は `ridecheck.js` (代表の駅だけ)。戸塚からの乗り継ぎは `node tools/dev/journeycheck.js <出力> [--to 舞浜]` (27 項目、約 40 分)。画面は `rideshot.js --station <駅> --from 東京 [--before 秒]`
5. 地上の区間 (段階 3b): 線の `viaduct` (m) で、鉄道中心線が「橋・高架」の所を地形からその高さだけ上げる (無ければ地面の高さ)。砕石の下面が地面より 1 m 以上高い所が高架 (`el`。橋桁・橋脚 `piers`)、地面より低くトンネルでない所が掘割 (地形を下げる)。地下の駅の次が地上の駅なら、その地上の駅に `depth: 0` を書く (地下の区間が浅くなっていき、駅の手前で地上に出る。書かないと深いまま来て、ホームが上り坂の途中になる)。高さの形は `routes[].p` の y と `dem0` を並べた縦断図で見る (段階 3b の記録)
6. 待避線のある駅 (葛西臨海公園: ホームに接するのは内側の 2・3 番線、外側は通過線) は、断面で番線を読み、線の `via: [{dir: "out" / "in", lat, lon}]` でホームに接する線を通す (その向きの道筋をたどるときに、点の 1.5 km 手前から最短のつながりでその点を通る)
- 同じ名前の駅 (東京) のホームは、横浜と同じ「のりかえ」の案内板でつながる (東京は京葉線・東海道線 上り・下りの 3 面。行き先は最大 2 つ)。地図の印は線ごとに別 (「東京駅（京葉線ホーム）」。`ride.js` の `stationSpots()` が名前と線 `sub` で分ける)

## PLATEAU の無い所の建物 (段階 4 で作った形。浦安市)
- 設定の `gsi_buildings`: `[{name, lon_min / lon_max / lat_min / lat_max (範囲), keep: {line, side: left / right} (その線の下りの進む向きのその側だけ)}]`。範囲の中の国土地理院の建物の輪郭 (`BldA`) を、種類からの推定の高さ (`GSI_BLD_H`) の箱にする
- PLATEAU があるか: `curl -s https://www.geospatial.jp/ckan/api/3/action/package_list` の名前の `plateau-<市区町村コード>-...` (浦安市 = 12227 は無かった)。全文検索の `package_search?q=plateau 浦安` は 0 件になるので当てにしない
- 範囲は PLATEAU のある市と重ならないように (重なると同じ建物が 2 つになる)。川などの境目の経度・緯度で切る

## 駅舎と駅前 (site。舞浜の高架の下の駅舎と北口で作った形)
- 設定の駅に `site` を書く (書き方は `data/rail_ext_config.json` の舞浜の `site._doc`)。座標は駅の向き: s = ホームの中心線 (最初 → 最後の点) の向き、t = 進む向きの左、原点はホームの中央の点。数字は m、高さは地面からの `floor` (改札の階)
- `rail_ext.py` の `site_frames` が `site.frame` (cx, cz, sx, sz, nx, nz, 地面 `gy` = `clear` の範囲の標高の中央値, ホーム `py`) を足し、`clear` の範囲の建物・木、`under` の範囲の橋脚を除く (`site_in`)。設定を変えたら `rail_ext.py` を実行し直す (2 回目からは 2〜3 分。変わるのは駅のまわりの区間と `index.json`)
- 描くのは `detail/stationsite.js` (`buildStationSite`。`railext.js` が駅の最初のホームのときに呼ぶ)。ホームの床の穴 (階段の口) は `siteCut` → `station.js` の床 (`rail.cut`)・`railext.js` の床の当たり判定と高架の駅のホームの下の面。穴の近くには屋根の柱・ベンチ・駅名標を置かない (`siteBlocked`)
- 歩ける床は `world.addColliders` の多角形 (上面に乗れる)。階段は踏み面ごとの多角形 (段差 0.17 m < `STEP` 0.4 m)。壁・手すりは線、柱は円。改札の階の下 (1 階) は中身の詰まった箱 (地上から入れない)
- 位置の決め方 (舞浜でやったこと): 航空写真 (国土地理院 `seamlessphoto` z18) を駅の向きの座標に並べ直し、国土地理院の建物の輪郭・道路を重ねた図を作る。Mapillary の写真の位置を s, t に直し、向き (`compass_angle`) を +s からの角度にして、どこから何を見た写真かを読む (北口の改札は s 30〜36、t 19 付近、デッキへの階段・車の回る所は s 60〜100)
- 確認: `node tools/dev/sitecheck.js` (歩かせる。17 項目。止まるかの確認は「歩き」で。走り・ダッシュではパルクールで手すりを飛び越える)、`node tools/dev/siteshot.js <出力> [--only 名前]` (視点は先頭の `VIEWS` に s, t で書く。修正前のデータでもホームの中心線から同じ座標を作る)
- ほかの駅に使うとき: 島式 1 面 2 線の高架駅なら同じ形で数字を変えるだけのはず (試していない)。地上の駅・橋上駅舎・地下の駅は形が違うので、`stationsite.js` に別の作りが要る

## いまの作りでできないこと (足すときはコードを直す)
- ホームの種類は `island`・`outer`・`inner` の 3 つ (`rail_ext.py` の `build_station`)。**相対式 (線路の外側に片面だけのホーム) は無い** (要るなら `outer` と同じく `side_track` で外側を測り、縁の片方を線路から固定の幅 (例 6 m) で作る種類を足す)。出力は `stations[].platforms`・`canopies` (ホームごと)。JS は古い形 (`platform`・`canopy` 1 つ) も読む
- 新しい線 (`lines`) は 1 本の上下線だけ。途中で分かれる・ほかの線へ乗り入れる、は扱っていない。2 番目の駅の向きで上下線を決めるので、最初の駅の中心で上下線が 15 m 以内に無いと作れない
- 新しい線のトンネルの出口 (段階 3b、潮見の手前): 坑口は既存の線と同じ形 (上下線でまとめて 1 つ)。掘割は地形を線路から 6.5 m 以内で下げるだけで、擁壁は無い (5 m の地形の格子なので斜面になる)
- 高架は橋桁 (箱) と 20 m おきの橋脚だけ。高さは設定の `viaduct` で一律 (実物の高さは調べていない)。高架の駅の駅舎・階段は、設定の `site` を書いた駅 (舞浜) だけ (上の「駅舎と駅前」)
- 地下の駅は、ホームと両側の線路を囲む箱 (壁・天井・照明) だけ。階段・改札・コンコースは無い。行き来は地図の印 (ワープ) と同じ名前の駅の「のりかえ」だけ
- 延長の先の駅はホームの上だけ (改札・駅舎の中・駅前は無い。ホームの縁に見えない柵。`site` を書いた舞浜だけは、高架の下の駅舎と北口の駅前を歩ける)。ホームが 2 面以上の駅は、ホームの中央の「のりかえ」の案内板の前で F / Q → 同じ駅のほかのホームへ (`ride.js` の `xfers`、`railext.js` の `xferSign`。設定は要らない。駅を足すと自動で付く)。地図の「電」の印 (「◯◯駅（ホーム）」、選ぶとホームへワープ) も駅を足すと自動で付く (`ride.js` の `stationSpots()`)
- 道筋の数は `props.json` の 6 本 (東海道・横須賀・貨物の上下) のまま。延長の先で線が分かれる・合流するのは扱っていない (たどるときは、分かれ道で一番まっすぐな線を選ぶ)

## はまった所 (同じ失敗をしない)
- **国土地理院のタイルの境目**: 同じ線路の線が、隣のタイルとの境目で 20 m ほど重なったり、すき間が空いたりする (端点ではつながらない)。`follow()` は「終わりの点から 1 m 以内を通る線」→ 無ければ「60 m 先までの延長線から 1.5 m 以内の線」に乗り移る
- **道筋と軌道の突き合わせ**: 端の点の近くの線分の「中点」で探すと、長い線分で別の線路を拾った。端から 15 m 内側の点と線分の距離 (1.5 m 以内・向きがそろう) で選ぶ。OSM と国土地理院の線路は 0.2 m ほどしかずれない
- **トンネル**: 標高タイルは地表なので、トンネルの上では山の高さになる (貨物線が 58 m まで上がった)。勾配の上限 2.5 % で線路を地形の下に入れ、地形がレールの下面より 7 m 以上高い区間 (40 m 以上続くもの) をトンネルとして坑口を置く。**40 m 未満は陸橋などの点の飛び** (東戸塚の手前で 1 か所あった)
- **線路の上の駅舎** (PLATEAU の箱が線路にかかる): 9 m 以上なら線路の上 6 m から (`lift`)、低いものは捨てる。屋根は片面で描く (中にカメラが入ると屋根の裏が画面いっぱいに出た)
- **電車の時刻**: 道筋が長くなると、1 本が走りきる時間 (`r.run`) が周期 (300 秒) を超える → 同じ道筋に `r.m` 本を同時に走らせる (`tOf(r, j, now)`)。**乗っている電車は出発の時刻 (`riding.dep`) で追う** (「何周期前の電車か」で追うと、周期が変わったとたんに別の電車へ移った)
- **発車の間隔**: 戸塚に着く時刻を周期の中の決まった位置にそろえる (`trains.js` の `ARRIVE_PHASE`、同じ向きの 2 線が 150 秒ずれ)。新しい駅の着く時刻はそこから決まる
- **地図の外の当たり判定**: `world.resolve` は位置を `world.bounds` に収めるので、広げないと地図の端へ引き戻される。地形の高さ `H()` も地図の外は端の値になるので、`setTerrainExt` で延長の地形を使う
- **ホームの当たり判定**: 床 (`poly`) と縁の柵 (`line`、高さ 1.2 m) を `world.addColliders(..., true)` で。戸塚駅では、描いていない古いホームの屋根 (`style: carport`) の当たり判定がキャラを押し出していた (main.js で外した)
- **確認の時計**: この環境は 1 コマ 1〜2 秒、画面 1 枚に 1〜2 分かかり、その間に電車が動く。確かめるときは `window.__trains.hold` で時刻を止め、`hold += 秒` で進める
- **断面の見方** (横浜で使った): 国土地理院の軌道 (`load_gsi`) から駅の中心 ±100 m の線分の主な向き (2 次モーメント) を求め、それに直角な線と交わる軌道の位置を並べる。最初は「いちばん近い線分の向き」を使って、短い渡り線の向きで斜めに切ってしまい、間の値が 1.25 倍ずれた
- **ホームの縁の線路を探す範囲**: `outer` の隣の線路は 5 m 以上離れたものから探す (自分の線路を拾わない)。分かれ目で見つからない・飛ぶ (中央値から 2 m 以上) 所は、間の中央値で埋める
- `rail_ext.json` は `props.json` の `rail.routes` の番号に結び付いている → **`build_props.py` を実行したら `rail_ext.py` も実行し直す**
- **分かれ道で留置線に入る** (段階 2、品川駅の北): 「いちばんまっすぐな線」だけで選ぶと、行き止まりの留置線 (札の辻の電留線) に入り、道筋が 34 km で止まった。分かれ道では候補ごとに `LOOK` (2 km) 先まで試しにたどり、遠くまで行けるものを選ぶ (同じなら点数)。横浜までの道筋はこれで変わらなかった
- **線路が十数本並ぶ駅では、上下線が隣の番線へ移る** (品川: 下り線が 12 番線ではなく 8 番線に入り、駅の北で上り線と同じ線路に合流した。上下線が同じ点で終わっていたら疑う)。断面で番線を読み、`via` で通る点を書く。たどり方を変えたら、道筋が地図の端から何 m まで以前と同じかを比べる (`--routes` の結果と前の全部入りの `routes[].p`)
- **断面の読み方** (品川・東京で使った): 島式ホームの両側の線路の間は 10〜16 m、ホームの無い隣どうしは 4〜6 m。Wikipedia の番線の並び (島式の組) と、間の並びを端から合わせる。新幹線・私鉄 (京急) の線も交じるので、まず両端のそれらを外す。番線の表の「主に◯番線」と道筋の通る番線が違ってもよい (東京の下りは 9・10 のどちらでも同じホーム)
- **市の境目の PLATEAU**: 市ごとに別の zip (`PLATEAU_SRC`)。境目のメッシュは両方の zip にあり、それぞれの市の建物だけが入っている → 両方読み、同じ位置・高さの建物は 1 つに。東京都 23 区 (2020) のファイル名は `<メッシュ>_bldg_6697_2_op.gml`。zip の中の一覧は `data/raw/plateau/<市>_names.json` に控える (開き直さない)
- **タイルが多すぎる**: 全部の駅を囲む 1 つの範囲にすると、東京まででは 4,000 枚を超える。区間ごとの範囲にした (1,304 枚。それでも道路の線は約 20 万本読むので、道路の「線路の近くか」も 100 m 升目で先に外す)
- **長くすると遅くなる所**: 細かい地形の「線路から 350 m 以内か」(1 点ずつ Python で判定すると東京まででは数時間) → numpy でまとめて (`near_mask`。判定の式は同じなので結果も同じ)。橋・トンネルの判定 (`profile`) は線分の索引。粗い地形は線路から 2.5 km 以内の点だけ値を作る (範囲全体だと標高タイルが 1,000 枚を超える)
- **標高タイルの値の無い所** (水面): 以前は 0 (= 地図の基準の高さ。海面より 14 m 上) にしていて、横浜駅の東の水面が盛り上がっていた → 海面の高さ (`dem0`)
- **地下にいるときの足元とカメラ** (段階 3a): `world.groundAt` は地形の高さ `H` より下には立たせないので、そのままでは地下のホームにワープすると地上へ飛び出し、カメラも「地面の下」とみなして寄ってしまう (コードを読んで先に直した。画面では起きていない)。→ 地下の駅の箱を `world.addUnderground({ring, floor, ceil})` で登録し、その輪郭の中で、高さが床〜天井の間にいる間だけ、地面の代わりに床を使う (`underAt`)。地上を歩いている人は、真下に駅があっても落ちない
- **地下の区間の電車を外から追うカメラ**: 外から回り込むと土の中に出る → トンネルの中では線路の上 (先頭の 14 m 前) から電車の前面を見る (`ride.js` の `view`)。最初は乗っている車両の 22 m 後ろの屋根の上からにしたら、画面が屋根だけになった
- **終点で止まる道筋**: 「最後に通った駅」を「その駅の止まる位置を 1 m 過ぎたら」にしていたので、終点に止まっている電車が消えると、1 つ手前の駅に戻された → 止まる位置に着いたら、その駅
- **空が黒くなる** (段階 3b、舞浜): 空の箱 (`main.js` の `Sky`、一辺 10 km) が原点に置いたままで、延長の先ではカメラが箱の外に出て、空の上半分が黒くなった (横浜のころから一部はそうだったはず)。→ 毎コマ `sky.position.copy(camera.position)`
- **通信が切れて止まる** (段階 3b): 国土地理院のタイル・PLATEAU の zip の読み込みで `Connection reset by peer` が 2 回出て、1 時間近くの実行が途中で止まった。→ 取り直す (`load_gsi`・`plateau_buildings`・`fetch_dem.tile`)。`fetch_dem` は以前、どんな失敗も「値の無いタイル」(= 海面) として控えていた (切れると地形が海面に落ちる)。今は 404 だけ
- **潮見のホームが坂の途中** (段階 3b): 地下の深さは駅の `depth` を線路に沿って補間するので、地上の駅 (潮見) に深さを書かないと線の `depth` (22 m) が使われ、トンネルが深いまま潮見の 400 m 手前まで来た → 潮見に `depth: 0`
- **建物・木の色**: 以前は全部の建物・木の通し番号から決めていたので、駅を足すとほかの所の色が全部ずれた → 位置から決める (`rail_ext_split.py` の `pos_hash`)。段階 2 でいちど全部の色が変わった (形は同じ)
